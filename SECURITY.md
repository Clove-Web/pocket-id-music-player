# Security Policy

The security of this project is important. We appreciate responsible disclosure from community members and security researchers.

## Supported Versions

Only the latest released version of this project receives security updates.

Older versions may not receive fixes and should not be relied upon for security patches.

## Reporting a Vulnerability

Please **do not report security vulnerabilities through public GitHub issues or discussions.**

Instead, report them privately by emailing:

**[admin@doughmination.win](mailto:admin@doughmination.win)**

Please include, where possible:

* A clear description of the issue.
* Steps to reproduce the vulnerability.
* The potential impact.
* Proof-of-concept code or screenshots, if appropriate.
* Any suggested mitigations.

Encrypted reports are welcome if required.

## Response Process

After receiving your report, we aim to:

1. Acknowledge receipt.
2. Investigate the report.
3. Determine whether the issue is valid.
4. Develop and test a fix where appropriate.
5. Notify you once the issue has been addressed.

Response times may vary depending on maintainer availability and the complexity of the issue.

## Responsible Disclosure

Please allow us reasonable time to investigate and resolve reported vulnerabilities before publicly disclosing them.

Responsible disclosure helps protect users while fixes are prepared and released.

## Good Faith Research

Security research conducted in good faith is welcomed.

Researchers are expected to:

* Avoid disrupting services.
* Avoid accessing or modifying data beyond what is necessary to demonstrate the issue.
* Respect user privacy.
* Report findings responsibly.
* Give maintainers a reasonable opportunity to resolve confirmed vulnerabilities.

## Scope

This policy applies to security vulnerabilities affecting this repository and its officially maintained releases.

## Questions

General security questions or licensing enquiries may also be directed to:
